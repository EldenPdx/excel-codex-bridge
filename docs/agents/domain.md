# Domain docs

This repo uses a single domain context.

## Before exploring a domain area

Read root `CONTEXT.md` if it exists. Read relevant decisions under root `docs/adr/` if they exist. Proceed when either is absent; the domain-modeling skill creates these files when terms or decisions are resolved.

## Layout

- `CONTEXT.md` — root domain glossary and context
- `docs/adr/` — architecture decisions

Use terms from `CONTEXT.md` in issues, proposals, hypotheses, and tests. If a needed term is absent, reconsider the name or note the gap for domain modeling.

Surface any conflict with an existing ADR explicitly, including the ADR and why the decision may need revisiting.
